## Purpose

The manual checks run for every release candidate before it goes to a client (doc 18 §14, manual row; §17 step 3). Automated tests cover the rules; this script covers what only a real Windows install, a real sign-in and a real Excel can show. The release owner runs it, records a result for every step, and signs section G. A failed step is a defect with its severity; release criterion 7 allows no open severity 1 or 2 defect.

Fill in the **Result** column with Pass, Fail (and the defect number) or N/A (with the reason). Keep the MSI logs, `register.log` files, `icacls` output and screenshots with the release record.

## Before you start

| Item | What is needed |
|---|---|
| The build | Both MSIs built by `tools/Build-Installer.ps1 -Platform both` from a commit tagged `data-platform/v<version>`, so the version is not `0.0.0`. For the upgrade steps, a second build with a higher version, and a rebuild with the same numeric version (another commit, or a release candidate and its release). |
| Virtual machines and snapshots | **VM-64**: Windows 11 x64 with 64-bit Microsoft 365 Apps. **VM-32**: Windows 11 x64 with 32-bit Microsoft 365 Apps. Each VM has three snapshots: **no runtime** (no .NET 10 Desktop Runtime), **own runtime** (only the runtime of its Office's bitness: x64 on VM-64, x86 on VM-32; this is the clean snapshot most steps start from) and **both runtimes** (the x64 and the x86 runtime). The runtime check runs first, on **no runtime**; the wrong-bitness check runs on **both runtimes**, so that only the bitness check can fail. For group H, one Intune-enrolled test device of each bitness (and an SCCM client, if the client uses SCCM). |
| Configuration | `C:\Deploy\DataPlatform\config.json` on each VM, pointing at the D8A test tenant and the test workspace with the sample model Inwards Analytics. |
| Accounts, by role | **Full access** (Viewer + Build, no RLS role), **RLS** (a row-level security role), **OLS** (an object-level security role that hides at least one column), **no access** (no access to the test workspace). Two Windows profiles on each VM: **profile 1**, created before the install, and **profile 2**, created after it. |
| The OLS role for group I | Besides the measure Outstanding Reserves, the OLS role hides at least one column (for example Broker Name) that group I puts on a matrix's Rows. If it hides no column, use a copy of the model with that column removed, as step I7 allows. |
| Excel settings | The native-query approval setting turned off for each account used in B to F (decision D-15), unless the step says otherwise. |
| Commands | Run `msiexec` from an elevated prompt with `/l*v "%TEMP%\DataPlatform-install.log"` added to every command (never a folder under `%ProgramData%\D8A`), and copy the log into the release record after each step, named after the step. Examples use the x64 names; on VM-32 use `DataPlatform-<version>-x86.msi` and `D8A.DataPlatform.xll`. Run the registration helper by hand only as the deployment guide section 8.1 shows: in PowerShell `$p = Start-Process -FilePath "<exe>" -ArgumentList '--unregister','"<xll>"' -Wait -PassThru; $p.ExitCode`, in `cmd` `start "" /wait "<exe>" --unregister "<xll>"` then `echo %ERRORLEVEL%`. The helper is a Windows (GUI) program, so without the wait the prompt returns before it has finished and its exit code (0 done, 1 wrong arguments, 2 failure) is lost. Record the exit code. |

## I. Attended acceptance scenarios (review §6)
